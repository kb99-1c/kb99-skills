# Задачи в Redmine

Задачи создаются через REST API от пользователя `bot` («bot claude»). Его ключ лежит в переменной окружения `REDMINE_API_KEY`. Все запросы идут только через [`Redmine.ps1`](Redmine.ps1) из этой папки: скрипт сам находит ключ (в том числе после `setx` без перезапуска), передаёт кириллицу в UTF-8 и не даёт создать задачу вне `v8_dev_vetis`.

```powershell
# Redmine.ps1 лежит в папке этого навыка — там же, где SKILL.md. В DSH это %USERPROFILE%\.dsh\skills\redmine-issues
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.dsh\skills\redmine-issues\Redmine.ps1" -Get trackers
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.dsh\skills\redmine-issues\Redmine.ps1" -NewIssue <файл.json> [-WhatIf]
```

## Справка

- Проект: `v8_dev_vetis` (id 285, «!v8_dev_vetis», родитель `!v8_dev`). Другие проекты — только если пользователь назвал их явно; тогда их нужно добавить в `$AllowedProjects` скрипта.
- Трекеры: 1 Ошибка, 2 Разработка, 3 Поддержка. Статусы: 1 Новая, 2 В работе, 3 Решена, 6 Завершена. Приоритеты (`priority_id`): 3 Низкий, 4 Нормальный (по умолчанию), 5 Высокий, 6 Срочный, 7 Немедленный. Если id не сходятся — `-Get trackers`, `-Get issue_statuses`, `-Get enumerations/issue_priorities`.
- Исполнители: `-Get projects/v8_dev_vetis/memberships`, в задачу передаётся `assigned_to_id`.
- Подзадачи: в JSON подзадачи — `parent_issue_id`. Проверка одним запросом: `-Get 'issues/<id>?include=children'` или `-Get 'issues?parent_id=<id>&status_id=*&limit=100'`. Строку запроса брать в одинарные кавычки — иначе `&` разберёт оболочка.
- Разметка описаний — **Textile**: `h3.` заголовки, `* ` списки, `@код@`, `<pre>` блоки.

## Шаги

1. **Черновик.** Источник — текст пользователя или ветка: `git log master..HEAD`, `git diff --stat master...HEAD`, `git status`. Изменения ветки сгруппировать по подсистемам из `docs/Architecture.xml`: одна задача — одна законченная доработка. Готово, когда каждое изменение ветки попало в задачу или явно оставлено без неё.
2. **Согласование.** Показать черновик таблицей: тема, трекер, статус, приоритет, исполнитель, описание в 1–2 строки. Создание — после явного «да» на этот черновик. Каждый новый черновик снова требует подтверждения.
3. **Файлы.** Для каждой задачи — JSON в scratchpad в UTF-8 (Write) по шаблону ниже.
4. **Первая задача.** Отправить одну с `-WhatIf`, затем без него; открыть её через `-Get issues/<id>` и проверить проект, трекер, тему, кириллицу.
5. **Остальные.** Отправить по одной, собирая вывод скрипта. Если это подзадачи — сверить их число одним запросом `include=children` у родителя.
6. **Отчёт.** Список `#id — тема — ссылка` по всем созданным задачам; если какая-то не создалась — код и текст ошибки.

## Шаблон задачи

```json
{
  "issue": {
    "project_id": "v8_dev_vetis",
    "tracker_id": 2,
    "status_id": 1,
    "priority_id": 4,
    "subject": "Глагол + объект доработки, до ~80 символов",
    "description": "h3. Что сделано\n\n* ...\n\nh3. Что осталось\n\n* ...\n\nh3. Затронуто\n\n* Подсистема: core\n* Модули: @ВетИС_ЯдроВызовСервера@\n* Ветка: @feat/GRACE_Rework@, коммиты: @2de248b8@"
  }
}
```

Для уже сделанной работы — `status_id: 3` (Решена). Раздел «Что осталось» убрать, если в нём пусто.

## Границы

Навык только создаёт задачи. Изменять, закрывать, комментировать или удалять существующие задачи — только по прямой просьбе пользователя для конкретных номеров. Значение ключа не появляется ни в чате, ни в файлах, ни в аргументах команд.
