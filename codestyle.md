## 1. Тексты модулей

> Стандарт: [Тексты модулей](https://its.1c.ru/db/v8std/content/456/hdoc) (std456)

### 1.1. Язык

Тексты модулей пишутся **на русском языке**.

Исключения:

- веб-сервисы — имена методов и параметров рекомендуется задавать на английском
  (например, метод `TestConnection` веб-сервиса `EnterpriseDataExchange`);
- идентификаторы сторонних информационных систем — например, названия полей «внешних»
  структур данных, которые программно обрабатываются в коде.

### 1.2. Запрещённые символы

| Запрет | Пояснение |
|---|---|
| Буква **«ё»** | Кроме интерфейсных текстов, выводимых пользователю в сообщениях, формах и справке, где употребление «ё» в ряде случаев допустимо |
| **Неразрывные пробелы** | Часто попадают при копировании из офисных документов |
| **Знак минус «-» в других кодировках** | Короткое, длинное тире и т.п. |

Почему это важно: ломается поиск фрагментов текста; некорректно выводятся подсказки типов
параметров в Конфигураторе и расширенная проверка в 1С:EDT; «неправильный» минус в выражении
даёт синтаксическую ошибку.

### 1.3. Чистота кода

- **Не должно быть неиспользуемых процедур и функций** (методическая рекомендация).
- **Не должно быть закомментированных фрагментов кода**, отладочного кода и служебных отметок
  процесса разработки (`TODO`, `MRG` и т.п.), а также упоминаний конкретных разработчиков.
  После завершения отладки или рефакторинга такой код удаляется.

```bsl
// Неправильно: отладочный код остался в обработчике
Процедура ПередУдалением(Отказ)
//    Если Истина Тогда
//        Сообщение("Для отладки");
//    КонецЕсли;
КонецПроцедуры

// Неправильно: служебная отметка с фамилией
Процедура ПередУдалением(Отказ)
    Если Истина Тогда
        // Иванов: доделать
    КонецЕсли;
КонецПроцедуры
```

Правильно — удалить обработчик `ПередУдалением` из кода, если он больше не нужен.

- **Нельзя модифицировать текст запроса комментариями** и затем «включать»/«выключать»
  фрагменты через `СтрЗаменить`. См. п. 6 стандарта
  [Оформление текстов запросов](https://its.1c.ru/db/v8std/content/437/hdoc).

```bsl
// Неправильно
ТекстЗапроса = "ВЫБРАТЬ
|	Контрагенты.Ссылка КАК Ссылка
|// ПОМЕСТИТЬ втКонтрагенты
|ИЗ
|	Справочник.Контрагенты КАК Контрагенты";

Если ВыгрузитьВоВременнуюТаблицу Тогда
	ТекстЗапроса = СтрЗаменить(ТекстЗапроса, "// ПОМЕСТИТЬ", "ПОМЕСТИТЬ");
КонецЕсли;
```

### 1.4. Один оператор в одной строке

Тексты модулей оформляются по принципу **«один оператор в одной строке»**.

Наличие нескольких операторов допускается только для «однотипных» операторов присваивания:

```bsl
НачальныйИндекс = 0; Индекс = 0; Результат = 0;
```

### 1.5. Отступы

- Текст модуля оформляется **синтаксическим отступом**.
- Для отступа используется **табуляция, а не пробелы** — чтобы при смене числа знаков
  в табуляции выравнивание сохранялось.
- Размер табуляции — стандартный, **4 символа**.

С крайней левой позиции начинаются только:

- операторы `Процедура`, `КонецПроцедуры`, `Функция`, `КонецФункции`;
- заголовки (описания) процедур и функций;
- объявление переменных модуля;
- код вне процедур и функций (с учётом синтаксического отступа);
- директивы компилятора `&НаКлиенте`, `&НаСервере` и т.д. и аннотации `&Перед`, `&После` и др.;
- инструкции препроцессора (в т.ч. `#Область` и `#КонецОбласти`).

`НачатьТранзакцию` и `ЗафиксироватьТранзакцию` **не являются операторными скобками** —
текст между ними не сдвигается.

```bsl
НачатьТранзакцию();
Попытка
    Движения.Записать();
    ЗафиксироватьТранзакцию();
Исключение
    ОтменитьТранзакцию();
    ВызватьИсключение;
КонецПопытки;
```

### 1.6. Длина строки и переносы

- При длине строки **более 120 символов** следует использовать переносы.
- Строки длиннее 120 символов делать не рекомендуется — кроме случаев, когда перенос
  невозможен (например, длинная строковая константа, выводимая без переносов в окно
  сообщений через `СообщениеПользователю`).

См. также [Перенос выражений](https://its.1c.ru/db/v8std/content/444/hdoc).

### 1.7. Комментарии

- Комментарии должны быть понятными и пояснять работу модуля или комментируемого оператора.
- Текст — по правилам русского языка, в деловом стиле, эмоционально сдержанный,
  без слов, не относящихся к функциональности программы.
- **Небольшой комментарий** пишется в конце строки, которую комментирует:

```bsl
НайденныеОшибки.Колонки.Добавить("Номер"); // для совместимости
```

- **Большой комментарий** (или комментарий к фрагменту кода) пишется перед кодом отдельной
  строкой, выравнивается по левой границе комментируемого фрагмента. Между `//` и текстом —
  пробел.

```bsl
// Инициализируем переменные для выполнения расчетов,
// которые выполняются далее по тексту модуля.
ТекущаяДата = ОбщегоНазначения.ПолучитьРабочуюДату();
ТекущийГод = Год(ТекущаяДата);
ТекущийМесяц = Месяц(ТекущаяДата);
```

### 1.8. Области внутри больших процедур

Тексты больших процедур и функций можно разбивать на сворачиваемые области. Имена областей
должны удовлетворять [правилам образования имён](#3-имена-переменных).

## 2. Структура модуля

> Стандарт: [Структура модуля](https://its.1c.ru/db/v8std/content/455/hdoc) (std455)

### 2.1. Порядок разделов

В программном модуле (общие модули, модули объектов, модули менеджеров объектов, модули
форм, команд и т.п.) в общем случае присутствуют разделы **в такой последовательности**:

1. заголовок модуля;
2. раздел описания переменных;
3. экспортные процедуры и функции модуля, составляющие его программный интерфейс;
4. обработчики событий объекта (формы);
5. служебные процедуры и функции модуля;
6. раздел инициализации.

Часть разделов присутствует только в модулях определённого вида: например, обработчики
событий элементов форм — только в модулях форм, а раздел описания переменных и раздел
инициализации не могут быть определены в неглобальных общих модулях, модулях менеджеров
объектов, наборов записей, значений констант и модуле сеанса.

Требование разделения кода на разделы повышает читаемость и упрощает внесение изменений
разными разработчиками. Объёмные разделы рекомендуется разбивать на подразделы
по функциональному признаку. Разделы и подразделы оформляются в виде **областей**;
имена областей — по [правилам образования имён](#3-имена-переменных).

### 2.2. Шаблон для общих модулей

```bsl
#Область ПрограммныйИнтерфейс
// Код процедур и функций
#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс
// Код процедур и функций
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
// Код процедур и функций
#КонецОбласти
```

- **Программный интерфейс** — экспортные процедуры и функции для использования другими
  объектами конфигурации или другими программами (например, через внешнее соединение).
- **Служебный программный интерфейс** — для модулей, входящих в функциональную подсистему:
  экспортные процедуры и функции, которые допустимо вызывать только из других функциональных
  подсистем этой же библиотеки.
- **Служебные процедуры и функции** — внутренняя реализация модуля. Для модуля, входящего
  в функциональную подсистему из нескольких объектов метаданных, здесь же размещаются
  служебные экспортные процедуры и функции, предназначенные только для вызова из других
  объектов этой подсистемы. Объёмный раздел разбивается на подразделы по функциональному
  признаку — например, `#Область ОбновлениеИнформационнойБазы`.

### 2.3. Шаблон для модулей объектов, менеджеров, наборов записей, обработок, отчётов

```bsl
#Область ОписаниеПеременных

#КонецОбласти

#Область ПрограммныйИнтерфейс
// Код процедур и функций
#КонецОбласти

#Область ОбработчикиСобытий
// Код процедур и функций
#КонецОбласти

#Область СлужебныйПрограммныйИнтерфейс
// Код процедур и функций
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
// Код процедур и функций
#КонецОбласти

#Область Инициализация

#КонецОбласти
```

- В **«Программный интерфейс»** не следует помещать экспортные процедуры и функции,
  предназначенные для вызова исключительно из модулей самого объекта, его форм и команд.
  Например, процедуры заполнения табличной части документа, вызываемые из обработки
  заполнения в модуле объекта и из формы документа, — это **не** программный интерфейс
  модуля объекта: их место в «Служебных процедурах и функциях».
- В **«Обработчики событий»** — обработчики событий модуля объекта (`ПриЗаписи`,
  `ПриПроведении` и др.).

### 2.4. Шаблон для модулей форм

```bsl
#Область ОписаниеПеременных

#КонецОбласти

#Область ОбработчикиСобытийФормы
// Код процедур и функций
#КонецОбласти

#Область ОбработчикиСобытийЭлементовШапкиФормы
// Код процедур и функций
#КонецОбласти

#Область ОбработчикиСобытийЭлементовТаблицыФормы<ИмяТаблицыФормы>
// Код процедур и функций
#КонецОбласти

#Область ОбработчикиКомандФормы
// Код процедур и функций
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
// Код процедур и функций
#КонецОбласти
```

- **Обработчики событий формы** — `ПриСозданииНаСервере`, `ПриОткрытии` и т.п.
- **Обработчики событий элементов шапки формы** — обработчики элементов основной части
  формы (всё, что не связано с таблицами).
- **Обработчики событий элементов таблицы формы <имя таблицы>** — для каждой таблицы
  формы создаётся свой раздел.
- **Обработчики команд формы** — обработчики команд, заданных в свойстве `Действие`.

### 2.5. Шаблон для модулей команд

```bsl
#Область ОбработчикиСобытий
// Код процедур и функций
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
// Код процедур и функций
#КонецОбласти
```

Раздел «Обработчики событий» содержит процедуру-обработчик команды `ОбработкаКоманды`.

### 2.6. Пустые области

**В модуле не должно быть пустых областей.**

### 2.7. Заголовок модуля

Заголовок модуля — комментарий в самом начале модуля с кратким описанием модуля
и условий его применения.

```bsl
////////////////////////////////////////////////////////////////////////////////
// Клиентские процедуры и функции общего назначения:
// - для работы со списками в формах;
// - для работы с журналом регистрации;
// - для обработки действий пользователя в процессе редактирования
//   многострочного текста, например комментария в документах;
// - прочее.
//
////////////////////////////////////////////////////////////////////////////////
```

Для модулей форм в заголовке рекомендуется размещать описание параметров формы.

### 2.8. Раздел описания переменных

- Имена переменных — по [общим правилам](#3-имена-переменных).
- **Все переменные модуля должны быть снабжены комментарием**, достаточным для понимания
  назначения. Комментарий рекомендуется размещать в той же строке, где объявляется переменная.

```bsl
#Область ОписаниеПеременных

Перем ВалютаУчета;
Перем АдресПоддержки;

#КонецОбласти
```

### 2.9. Внутренний порядок разделов

- **Программный интерфейс** размещается сразу после описания переменных — на «видном месте»,
  так как предназначен для внешних потребителей.
- **Обработчики событий формы, команд и элементов формы** располагаются перед служебными
  процедурами и функциями модуля формы.
  - Рекомендуется располагать обработчики одного элемента формы вместе, придерживаясь
    порядка их следования в панели свойств редактора формы.
  - **У каждого события должна быть своя процедура-обработчик.** Если одинаковые действия
    нужны при событиях разных элементов — создаётся отдельная процедура (функция), а из
    каждого обработчика (с именем по умолчанию) она вызывается.
- **Обработчики событий модулей объекта и менеджера объекта** размещаются после раздела
  с программным интерфейсом, но до служебных процедур и функций. Рекомендуется придерживаться
  порядка их следования в описании встроенного языка.
- **Служебные процедуры и функции** — следом за обработчиками событий. Процедуры и функции,
  связанные по характеру или логике работы, располагаются вместе. В модулях форм **не
  рекомендуется** группировать процедуры на серверные, клиентские и без контекста: такое
  «технологическое» упорядочивание затрудняет понимание логики модуля.
- **Раздел инициализации** содержит операторы, инициализирующие переменные модуля или объект
  (форму).

```bsl
// Неправильно: один и тот же код в двух обработчиках, один вызывает другой через
// подстановку имени события
&НаКлиенте
Процедура ПоИсполнителюПриИзменении(Элемент)
    ПараметрыОтбора = Новый Соответствие();
    ПараметрыОтбора.Вставить("ПоАвтору", ПоАвтору);
    ПараметрыОтбора.Вставить("ПоИсполнителю", ПоИсполнителю);
    УстановитьОтборСписка(Список, ПараметрыОтбора);
КонецПроцедуры

&НаКлиенте
Процедура ПоАвторуПриИзменении(Элемент)
    ПоИсполнителюПриИзменении(Неопределено);
КонецПроцедуры

// Правильно: у каждого события свой обработчик, общая логика — в отдельной процедуре
&НаКлиенте
Процедура ПоИсполнителюПриИзменении(Элемент)
    УстановитьОтбор();
КонецПроцедуры

&НаКлиенте
Процедура ПоАвторуПриИзменении(Элемент)
    УстановитьОтбор();
КонецПроцедуры

&НаСервере
Процедура УстановитьОтбор()
    ПараметрыОтбора = Новый Соответствие();
    ПараметрыОтбора.Вставить("ПоАвтору", ПоАвтору);
    ПараметрыОтбора.Вставить("ПоИсполнителю", ПоИсполнителю);
    УстановитьОтборСписка(Список, ПараметрыОтбора);
КонецПроцедуры
```

## 3. Имена переменных

> Стандарт: [Правила образования имен переменных](https://its.1c.ru/db/v8std/content/454/hdoc) (std454)

1. Имена образуются от **терминов предметной области** так, чтобы назначение было понятно
   из имени.
2. Пробелы между словами удаляются, **каждое слово — с прописной буквы**. Предлоги
   и местоимения из одной буквы пишутся прописными буквами.

   ```bsl
   Перем ДиалогРаботыСКаталогом;     // Диалог работы с каталогом
   Перем КоличествоПачекВКоробке;    // Количество пачек в коробке
   ```

   Некорректные имена: `масРеквизитов`, `соотвВидИмя`, `новСтр`.
3. **Запрещается** начинать имя с подчёркивания.
4. Имя **не должно состоять из одного символа**. Односимвольные имена допустимы только
   для счётчиков циклов.
5. Переменные-флаги называются так, как пишется **истинное** значение флага:

   ```bsl
   Перем ЕстьОшибки;     // Признак наличия ошибок в процедуре.
   Перем ЭтоТоварТара;   // Признак, что товар относится к возвратной таре.
   ```

Имена областей подчиняются этим же правилам.

## 4. Имена процедур и функций

> Стандарт: [Имена процедур и функций](https://its.1c.ru/db/v8std/content/647/hdoc) (std647)

Хорошо выбранное имя процедуры вместе с правильно подобранными именами параметров избавляет
от необходимости её дополнительно описывать. Если «самодокументирующееся» имя придумать
легко — процедура спроектирована правильно; если трудно — это признак неправильной
архитектуры кода.

### 4.1. Общие требования

- Имена процедур, функций и формальных параметров образуются от терминов предметной области;
  из имени должно быть понятно назначение. Имена должны быть «говорящими».

```bsl
// Неправильно
Функция ВыполнитьПроверку(Параметр1, Рекв, ТЗ)

// Правильно
Функция РеквизитОбъектаЗаданногоТипа(Объект, ИмяРеквизита, ТипЗначения)
```

- Слова пишутся слитно, каждое — с прописной буквы; предлоги и местоимения из одной буквы —
  тоже прописными.
- **Не рекомендуется описывать в имени типы** принимаемых параметров и (или) возвращаемых
  значений.

```bsl
// Неправильно
Функция ПолучитьМассивРолейСПравомДобавления()
Функция ПолучитьСтруктуруДополнительныхНастроек()

// Правильно
Функция ИменаРолейСПравомДобавления()
Функция ДополнительныеНастройки()
```

Рекомендация справедлива в большинстве случаев; исключение — когда без указания типа
возвращаемого значения не ясно назначение самой функции.

### 4.2. Процедуры

Имя процедуры образуется от **неопределённой формы глагола**, от сути выполняемого действия:

```bsl
// Неправильно
Процедура ЗагрузкаКонтрагента()

// Правильно
Процедура ЗагрузитьКонтрагента()
```

### 4.3. Функции

- В общем случае имя функции образуется **от описания возвращаемого значения**:

```bsl
// Неправильно
Функция ПолучитьПолноеИмяПользователя()
Функция СоздатьПараметрыЗаполненияЦенПоставщика()
Функция ОпределитьДатуНачалаСеанса()

// Правильно
Функция ПолноеИмяПользователя()
Функция НовыеПараметрыЗаполненияЦенПоставщика()
Функция ДатаНачалаСеанса()
```

- Если функция **создаёт объект**, в имени рекомендуется использовать слово «Новый»:

```bsl
// Неправильно: ДобавитьПолеФормы(), СоздатьЭлементСправочникаФайлы(), ПолучитьТаблицуКоманд()
// Правильно:   НовоеПолеФормы(),   НовыйЭлементСправочникаФайлы(),   НоваяТаблицаКоманд()
```

- Если функция **проверяет условие**, имя рекомендуется начинать со слова «Это» или
  использовать причастия:

```bsl
// Неправильно: ПроверитьПроведенностьДокумента(), ПроверитьИзменениеРеквизитовДокумента(), ВнешняяЗадача()
// Правильно:   ДокументПроведен(),              РеквизитыДокументыИзменены(),              ЭтоВнешняяЗадача()
```

- Глагол в неопределённой форме используется и в имени функции, когда для понимания назначения
  важно, **каким образом** получено возвращаемое значение:

```bsl
Функция ВыбратьДанныеПоПравилу(Правило, ПользовательскиеНастройки)
Функция ПреобразоватьДанныеПоПравилу(НаборыДанных, ПараметрыПреобразования)
```

- Если работа функции — прежде всего действие, а возврат значения не основная задача
  (например, признак успешности), имя образуется от неопределённой формы глагола, как
  для процедуры:

```bsl
Функция РазрешитьРедактированиеРеквизитовОбъекта(Форма)
```

## 5. Описание процедур и функций

> Стандарт: [Описание процедур и функций](https://its.1c.ru/db/v8std/content/453/hdoc) (std453)

Описание выполняется в виде комментария. Текст комментария в 8.3 выводится в контекстной
подсказке процедур, функций и их параметров, а в 1С:EDT используется для уточнения типизации
параметров и возвращаемого значения и помогает выявлять ошибки на этапе разработки.

### 5.1. Что комментировать обязательно

- **Обязательно** комментируются процедуры и функции, входящие в
  [программный интерфейс модуля](#2-структура-модуля): за них могут отвечать другие
  разработчики, они должны быть хорошо документированы.
- Прочие процедуры и функции (в т.ч. обработчики событий) комментируются, если нужно пояснить
  назначение или особенности работы, а также причины невыполнения некоторых действий, если
  они неочевидны. Если назначение и порядок работы следуют из названия и имён формальных
  параметров — комментарий можно не писать.
- **Следует избегать комментариев, не дающих дополнительных пояснений** о работе
  неэкспортной процедуры (функции):

```bsl
// Неправильно: избыточно, назначение очевидно из имени
// Процедура - обработчик события "ПриОткрытии" формы
&НаКлиенте
Процедура ПриОткрытии()

// Неправильно: не даёт никакой дополнительной информации
// Функция возвращает статью движения денежных средств по данным документа
Функция СтатьяДвиженияДенежныхСредств(ДанныеДокумента)
```

### 5.2. Состав комментария

Комментарий размещается **перед объявлением** процедуры (функции) и состоит из секций.

#### Секция «Описание»

Содержит описание назначения, достаточное для понимания сценариев использования без просмотра
исходного кода; может содержать краткое описание принципов работы и перекрёстные ссылки.
Может быть единственной секцией для процедур без параметров.

- Описание **не должно совпадать с именем** процедуры (функции).
- Начинается **с глагола**. Для функций, как правило: «Возвращает…». Если возвращаемый
  результат не основной — с основного действия: «Проверяет…», «Сравнивает…», «Вычисляет…».
- Не рекомендуется начинать с избыточных «Процедура…», «Функция…» и с имени самой процедуры.

```bsl
// Неправильно
// Конструктор объекта WSПрокси.
Функция WSПрокси(ПараметрыПрокси) Экспорт

// Функция СтрокаТаблицыЗначенийВСтруктуру создает структуру со свойствами, ...
Функция СтрокаТаблицыЗначенийВСтруктуру(СтрокаТаблицыЗначений) Экспорт

// Правильно
// Создает прокси на основе определения веб-сервиса и связывает
// его с точкой подключения веб-сервиса.
// В дополнении к платформенному конструктору Новый WSПрокси:
//  - включает в себя вызов конструктора WSОпределения;
//  - на время сеанса кэширует файл WSDL для оптимизации частых обращений к веб-сервису;
//  - не требует явного указания ИнтернетПрокси (он подставляется автоматически, если настроен);
//  - выполняет быструю проверку доступности веб-сервиса с помощью операции Ping.
Функция WSПрокси(ПараметрыПрокси) Экспорт
```

#### Секция «Параметры»

Пропускается, если параметров нет. Предваряется строкой `Параметры:`, далее с новой строки
описания всех параметров.

Формат описания параметра:

```
//  ИмяПараметра - Тип[, Тип...] - текстовое описание
```

- **Имя параметра** выбирается так, чтобы назначение было понятно в контексте функции.
- **Описание типа обязательно.** Тип может быть указан один или список через запятую; имя типа
  простое (`Строка`, `Структура`, `Произвольный`) или составное через точку
  (`СправочникСсылка.Сотрудники`).

  В качестве типов используются только существующие в платформе типы, а также специальные
  типы EDT: `ОпределяемыйТип.<Имя>`, `СправочникСсылка`, `ОбъектМетаданныхОтчет`,
  `РасширениеДекорацииФормыДляНадписи` и т.п.

  ```bsl
  // Неправильно
  // КоллекцияСтрок - КоллекцияЗначений – коллекция для сравнения;
  // ФормируемыйОтчет - ОбъектМетаданных: Отчет
  // ПрисоединенныйФайлОбъект - элемент справочника файлов.

  // Правильно
  // КоллекцияСтрок – ТаблицаЗначений, Массив, СписокЗначений – коллекция для сравнения.
  // ФормируемыйОтчет – ОбъектМетаданныхОтчет
  // ПрисоединенныйФайлОбъект - ОпределяемыйТип.ПрисоединенныйФайлОбъект - элемент справочника файлов.
  ```

- **Текстовое описание** заполняется, когда одного имени параметра в контексте функции
  недостаточно: чтобы пояснить назначение, дать дополнительную информацию о типе, указать
  правило передачи нескольких значений, привести наглядный пример.

  ```bsl
  // Неправильно
  // Параметры:
  //  Адреса - Строка - строка, содержащая электронные адреса
  //  ЗадачаИсполнителя - ЗадачаСсылка.ЗадачаИсполнителя – проверяемая задача

  // Правильно
  // Параметры:
  //  Адреса - Строка - содержит электронные адреса, разделенные запятой.
  //           Например, support@mycorp.ru,v8@localdomain.
  //  ЗадачаИсполнителя - ЗадачаСсылка.ЗадачаИсполнителя
  ```

- Для параметров типа `Структура`, `ТаблицаЗначений`, `ДеревоЗначений` в описании типа
  указывается ссылка на функцию, выходным значением которой является эта структура или
  таблица значений (см. [раздел 7](#7-структуры-и-таблицы-значений-как-параметры)):

  ```bsl
  //  ПараметрыЗаполненияЦен – см. ЦенообразованиеСервер.ПараметрыЗаполненияЦен
  ```

  В редких случаях, когда метод обрабатывает коллекции универсальным образом, достаточно
  указать просто `Структура` или `ТаблицаЗначений` (`ДеревоЗначений`).

- Для параметров типа `Массив` указывается тип элементов с помощью ключевого слова **«из»**
  (англ. `of`). Не указывать тип элементов допустимо только в методах, работающих с массивами
  универсальным образом.

  ```bsl
  // Неправильно
  // МассивПеренаправленныхЗадач - Массив - массив перенаправленных задач.

  // Правильно
  // СведенияОбОбновлении - Массив из см. ОбновлениеИнформационнойБазы.ПараметрыОбновления
  ```

- Для параметра типа `СтрокаТаблицыЗначений` (`СтрокаДереваЗначений`) можно задать состав
  свойств, соответствующий колонкам таблицы-владельца:

  ```bsl
  // СведенияОРегионе – СтрокаТаблицыЗначений: см. РегистрыСведений.АдресныеОбъекты.КлассификаторСубъектовРФ
  ```

- Каждому параметру можно задать **одно или несколько дополнительных описаний типов**:
  каждое с новой строки, затем обязательный дефис, список типов, дефис и текстовое описание.

  ```bsl
  // Параметры:
  //   Реквизиты - Строка - имена реквизитов, перечисленные через запятую.
  //                        Например, "Код, Наименование, Родитель".
  //             - Структура, ФиксированнаяСтруктура - в качестве ключа передается
  //                        псевдоним поля для возвращаемой структуры с результатом,
  //                        а в качестве значения (опционально) фактическое имя поля в таблице.
  //                        Если значение не определено, то имя поля берется из ключа.
  //             - Массив Из Строка, ФиксированныйМассив Из Строка - имена реквизитов.
  ```

- Описание может быть задано **ссылкой на функцию-конструктор** в формате «см. ПутьКФункции»
  (англ. `see MethodPath`). При обращении к реквизитам конкретного объекта метаданных
  или формы можно ссылаться на типы его реквизитов:

  ```bsl
  //  Запросы - см. Обработка.КонсольЗапросов.ТабличнаяЧасть.Запросы
  //  ТипыДанных - см. Обработка.КонсольЗапросов.Реквизит.ДоступныеТипыДанных
  //  Вложения - см. Справочник.ШаблоныСообщений.ФормаЭлемента.Вложения
  ```

  В редких случаях, когда подходящей функции-конструктора нет и её невозможно создать,
  допустима ссылка на параметр другой процедуры или функции.

- Если процедура является событием, описанным в программном интерфейсе (например,
  в переопределяемом модуле) и повторяет его состав и порядок параметров, рекомендуется
  использовать одну ссылку на такую процедуру:

  ```bsl
  // См. ОтчетыПереопределяемый.ПриСозданииНаСервере
  Процедура ПриСозданииНаСервере(Форма, Отказ, СтандартнаяОбработка) Экспорт
  ```

#### Секция «Возвращаемое значение»

Для процедур отсутствует. Предваряется строкой `Возвращаемое значение:`, затем с новой
строки тип, дефис и текст описания. Для составного типа каждый тип — с новой строки с дефиса.

```bsl
// Возвращаемое значение:
//  Строка

// Возвращаемое значение:
//  Булево - Истина, если хотя бы одна из переданных ролей доступна текущему пользователю,
//           либо у него есть административные права.

// Возвращаемое значение:
//  - ЛюбаяСсылка - ссылка на предопределенный элемент.
//  - Неопределено - если предопределенный элемент есть в метаданных, но не создан в ИБ.

// Возвращаемое значение:
//  - СправочникСсылка.Пользователи
//  - СправочникСсылка.ВнешниеПользователи
```

Текстовое описание заполняется, когда одного описания функции недостаточно или нужно дать
дополнительную информацию о типе (состав свойств или колонок), привести пример ожидаемого
значения. Формат для `Массив` — как для параметров, для `Структура` и `ТаблицаЗначений` —
см. [раздел 7](#7-структуры-и-таблицы-значений-как-параметры).

#### Секция «Пример»

Предваряется строкой `Пример:`, далее с новой строки пример использования. Имя процедуры
(функции) пишется **вместе с именем общего модуля**, в котором она расположена. Из примера
должно быть понятно, что передаётся на входе и что возвращается на выходе.

```bsl
// Неправильно
// Пример:
//  ПодставитьПараметрыВСтроку(ШаблонСтроки, СтрокаЗамены);

// Правильно
// Пример:
//  СтроковыеФункцииКлиентСервер.ПодставитьПараметрыВСтроку(НСтр("ru='%1 пошел в %2'"), "Вася", "Зоопарк") = "Вася пошел в Зоопарк".
```

В [переопределяемых модулях](https://its.1c.ru/db/v8std/content/554/hdoc) в секции «Пример»
размещается пример **реализации** переопределяемой процедуры, а не её вызова:

```bsl
// Пример:
//  ОбщиеПараметры.МинимальноНеобходимаяВерсияПлатформы = "8.3.4.365";
//  ОбщиеПараметры.РекомендуемыйОбъемОперативнойПамяти = 2;
```

#### Секция «Варианты вызова»

Добавляется в редких случаях, когда сразу несколько параметров имеют дополнительные типы.
Начинается фразой `Варианты вызова:`; каждый вариант — имя функции со списком типов
в круглых скобках, дефис и описание.

```bsl
// Параметры:
//   Параметр1 - Тип11, Тип12        - ...
//   Параметр2 - Тип21, Тип22, Тип23 - ...
//
// Варианты вызова:
//   УниверсальнаяПроцедура(Тип11, Тип21) - описание ...
//   УниверсальнаяПроцедура(Тип12, Тип22) - описание ...
//
Процедура УниверсальнаяПроцедура(Параметр1, Параметр2) Экспорт
```

### 5.3. Отступы в комментарии

Текст комментария во всех объявляемых секциях имеет отступ относительно заголовка секции,
начиная с первой строки. В многострочном описании, относящемся к одному контексту,
дополнительный отступ требуется только для второй строки; последующие строки выравниваются
по одной вертикали со второй.

```bsl
// Первая строка описания универсальной процедуры.
// Вторая строка пишется без отступа, т.к. секция «Описание» не объявляемая.
//
// Параметры:
//   Параметр1 – Тип1 - первая строка описания параметра,
//     Вторая строка имеет смещение по отношению к первой.
//     Третья строка пишется без дополнительного смещения.
//   Параметр2 – Тип2 - Здесь начинается новый контекст.
//
Процедура УниверсальнаяПроцедура(Параметр1, Параметр2)
```

Отступы нужны для однозначного визуального разделения структуры комментария и корректного
отнесения текста к секции автоматизированными средствами при ошибках оформления.

### 5.4. Переходы и пометка «Устарела»

- В любом месте комментария можно добавить переход к другим объектам конфигурации, процедурам
  и функциям. В 1С:EDT такие переходы оформляются гиперссылкой.

  ```bsl
  // Описание универсальной процедуры.
  //
  // См. УправлениеДоступом.ЗаполнитьНаборыЗначенийДоступа
  //
  // Параметры:
  //   Параметр1 – Произвольный – описание параметра см. Справочник.Контрагенты.
  //
  Процедура УниверсальнаяПроцедура(Параметр1)
  ```

- Устаревшая процедура (функция) помечается словом **«Устарела»** (англ. `Deprecated`)
  в первой строке описания:

  ```bsl
  // Устарела. Следует использовать см. ОбщегоНазначения.РазделениеВключено и
  // см. ОбщегоНазначения.ДоступноИспользованиеРазделенныхДанных
  Функция ИспользованиеРазделителяСеанса() Экспорт
  ```

### 5.5. Комментарий и директива компиляции

Комментарий размещается **до** директивы компиляции. Такой порядок позволяет сначала
обратить внимание на определение функции и директиву, а потом — на комментарий, который
может занимать много строк.

```bsl
// Процедура - обработчик события формы ПриСозданииНаСервере.
// Обрабатывает параметры формы и заполняет реквизиты формы значениями.
//
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
```

### 5.6. Разделение процедур

Код процедур и функций должен отделяться друг от друга **пустыми строками**.

### 5.7. Полный пример

```bsl
// Определяет доступность ролей ИменаРолей текущему пользователю,
// а также доступность административных прав.
//
// Параметры:
//   ИменаРолей - Строка - имена ролей, доступность которых проверяется, разделенные запятыми.
//
// Возвращаемое значение:
//   Булево - Истина, если хотя бы одна из переданных ролей доступна текущему пользователю,
//            либо у него есть административные права.
//
// Пример:
// Если РолиДоступны("ИспользованиеРассылокОтчетов,ОтправкаПоПочте") Тогда ...
//
Функция РолиДоступны(ИменаРолей) Экспорт
```

## 6. Параметры процедур и функций

> Стандарт: [Параметры процедур и функций](https://its.1c.ru/db/v8std/content/640/hdoc) (std640)

### 6.1. Объявление

- Имена параметров — по [общим правилам образования имён](#3-имена-переменных): от терминов
  предметной области, назначение понятно из имени.
- **Не следует использовать вместо параметров** другие средства конфигурирования
  (переменные модулей, реквизиты формы и т.п.).
- Параметры идут **в логической последовательности**, по принципу «от общего к частному».

```bsl
// Неправильно
Процедура ПересчитатьСуммуДокумента(ИмяПоляСумма, ДокументОбъект, СуммаВключаетНДС = Истина)
Процедура ПоменятьЦветПоляФормы(Цвет, ИмяПоля, Форма)

// Правильно: сначала основные параметры
Процедура ПересчитатьСуммуДокумента(ДокументОбъект, ИмяПоляСумма, СуммаВключаетНДС = Истина)
Процедура ПоменятьЦветПоляФормы(Форма, ИмяПоля, Цвет)
```

- **Необязательные параметры** (со значениями по умолчанию) — **после обязательных**.

```bsl
Функция КурсВалютыНаДату(Валюта, Дата = Неопределено) Экспорт
```

### 6.2. Количество параметров

- Не рекомендуется объявлять много параметров: ориентир — **не более семи**, из них
  со значениями по умолчанию — **не более трёх**. Иначе читаемость вызывающего кода резко
  падает (легко ошибиться в количестве запятых).

Если параметров много:

- группировать однотипные параметры в один или несколько составных параметров типа
  `Структура` (например, `ДанныеЗаполнения`, `ПараметрыПроведения`, `ДанныеФайла`);
- либо пересмотреть логику функции, разделив её на несколько более простых.

```bsl
// Неправильно
Функция ДобавитьПолеФормы(ИмяПоля, Заголовок = Неопределено, ОбработчикПриИзменении = "",
    ОбработчикНачалоВыбора = "", ШиринаПоля, ЦветФона = Неопределено, ...)

// Правильно: один ключевой параметр, остальное настраивается у результата
Функция НовоеПолеФормы(ИмяПоля)
...
КонецФункции

НовоеПоле = НовоеПолеФормы("СтараяЦена");
НовоеПоле.Заголовок  = НСтр("ru='Цена'");
НовоеПоле.ЦветФона   = ЦветФона;
```

```bsl
// Неправильно
Процедура СоздатьЭлементНоменклатуры(Наименование, ТоварУслуга, ЕдиницаИзмерения, ВесНетто,
    ПроверятьУникальность = Истина)

// Правильно: значения реквизитов сгруппированы в структуру
Процедура СоздатьЭлементНоменклатуры(ЗначенияРеквизитов, ПроверятьУникальность = Истина)
```

### 6.3. Вызов

- **Избегать вложенных вызовов** при передаче параметров — они снижают читаемость, повышают
  вероятность ошибок и затрудняют отладку. Разбивать на отдельные операторы с помощью
  локальных переменных.

```bsl
// Неправильно
СтруктураВложений.Вставить(ПрисоединенныйФайл.Наименование,
    Новый Картинка(ПолучитьИзВременногоХранилища(ПрисоединенныеФайлы.ПолучитьДанныеФайла(
        ПрисоединенныйФайл.Ссылка).СсылкаНаДвоичныеДанныеФайла)));

// Правильно
АдресФайлаИзображения = ПрисоединенныеФайлы.ПолучитьДанныеФайла(
    ПрисоединенныйФайл.Ссылка).СсылкаНаДвоичныеДанныеФайла;
ДанныеИзображения = Новый Картинка(ПолучитьИзВременногоХранилища(АдресФайлаИзображения));
СтруктураВложений.Вставить(ПрисоединенныйФайл.Наименование, ДанныеИзображения);
```

Вложенные вызовы допустимы, если код остаётся компактным (не требует переноса выражений)
и легко читаемым:

```bsl
Предупреждение(НСтр("ru='Для выполнения операции необходимо установить расширение работы с файлами.'"));
ПеречитатьСуммуПоКурсу(Сумма, КурсВалютыНаДату(Валюта));
```

- **Не рекомендуется вложенный конструктор структуры** `Новый Структура(...)`. Допустимо,
  только если свойств немного (ориентир — **не более трёх**).

```bsl
// Неправильно
ЗаполнитьЦены(Объект.Товары, ,
    Новый Структура("Дата, Валюта, Соглашение, ПоляЗаполнения",
        Объект.Дата, Объект.Валюта, Объект.Соглашение, "Цена, СтавкаНДС, ВидЦены, СрокПоставки"),
    Новый Структура("ПересчитатьСумму, ПересчитатьСуммуСНДС, ПересчитатьСуммуНДС, ...", ...));

// Правильно
ПараметрыЗаполнения = Новый Структура;
ПараметрыЗаполнения.Вставить("Дата", Объект.Дата);
ПараметрыЗаполнения.Вставить("Валюта", Объект.Валюта);
ПараметрыЗаполнения.Вставить("Соглашение", Объект.Соглашение);
ПараметрыЗаполнения.Вставить("ПоляЗаполнения", "Цена, СтавкаНДС, ВидЦены, СрокПоставки");

ДействияСИзмененнымиСтроками = Новый Структура;
ДействияСИзмененнымиСтроками.Вставить("ПересчитатьСумму", "КоличествоУпаковок");

ЗаполнитьЦены(Объект.Товары, ПараметрыЗаполнения, ДействияСИзмененнымиСтроками);
```

- При вызове методов, процедур и функций **не допускаются пробелы**:
  перед открывающей скобкой, после открывающей скобки, перед закрывающей скобкой,
  перед запятыми (при размещении параметров в одной строке и если параметры не опущены).

```bsl
// Неправильно
НовоеПоле = НовоеПолеФормы ( ИмяПоля , ТипПоля );

// Правильно
НовоеПоле = НовоеПолеФормы(ИмяПоля, ТипПоля);
```

- **Не следует пропускать обязательные параметры**: в параметр будет передано `Неопределено`,
  на которое функция может быть не рассчитана. Если `Неопределено` допустимо — передавать
  явно либо сделать параметр необязательным со значением по умолчанию `Неопределено`.

```bsl
// Неправильно: пропущен обязательный первый параметр Форма
ПоменятьЦветПоляФормы(, "РезультатПроверки", ЦветаСтиля.ПоясняющийОшибкуТекст);

// Правильно
ПоменятьЦветПоляФормы(ЭтотОбъект, "РезультатПроверки", Цвет);
```

## 7. Структуры и таблицы значений как параметры

> Стандарт: [Особенности использования структур в качестве параметров](https://its.1c.ru/db/v8std/content/641/hdoc) (std641)

Все рекомендации для таблицы значений относятся также к дереву значений.

### 7.1. Функция-конструктор параметров

Помимо функции, реализующей прикладную функциональность (**вызываемая функция**), определяется
**функция-конструктор параметров**, возвращающая:

- структуру-заготовку со свойствами, либо
- пустую таблицу значений (дерево значений) с типизированными колонками.

Вызывающий код должен проинициализировать её конкретными значениями и передать
в вызываемую функцию.

```bsl
Процедура ПриИзмененииНоменклатурыСервер(ИдентификаторТекущейСтроки)

    // Получаем новую структуру параметров.
    ПараметрыЗаполненияЦен = ЦенообразованиеКлиентСервер.ПараметрыЗаполненияЦеныВСтрокеТЧ();
    // Заполняем параметры.
    ПараметрыЗаполненияЦен.Дата   = Объект.Дата;
    ПараметрыЗаполненияЦен.Валюта = Объект.Валюта;

    ТекущаяСтрока = Объект.Товары.НайтиПоИдентификатору(ИдентификаторТекущейСтроки);

    // Передаем структуру параметров в прикладную функцию.
    ЦенообразованиеСервер.ЗаполнитьЦеныВСтрокеТЧ(ТекущаяСтрока, ПараметрыЗаполненияЦен);

КонецПроцедуры
```

```bsl
// Функция-конструктор параметров процедуры ЦенообразованиеСервер.ЗаполнитьЦеныВСтрокеТЧ.
//
// Возвращаемое значение:
//  Структура:
//        * Дата – Дата
//        * Валюта - СправочникСсылка.Валюты
//        * ПересчитыватьСумму - Булево
//
Функция ПараметрыЗаполненияЦеныВСтрокеТЧ() Экспорт

    ПараметрыЗаполненияЦен = Новый Структура;
    ПараметрыЗаполненияЦен.Вставить("Дата", ТекущаяДатаСеанса());
    ПараметрыЗаполненияЦен.Вставить("Валюта", ОсновнаяВалюта());
    ПараметрыЗаполненияЦен.Вставить("ПересчитыватьСумму", Истина);
    Возврат ПараметрыЗаполненияЦен;

КонецФункции
```

- Имена свойств структуры соответствуют параметрам вызываемой функции. **Параметры
  со значениями по умолчанию должны быть явно проинициализированы** в этой структуре.
- Для типа `ТаблицаЗначений` допускается не создавать отдельную функцию-конструктор, если
  таблица значений является результатом расчётов в прикладном коде (например, есть функция,
  которая делает запрос и передаёт результат в другую функцию в виде таблицы значений).

### 7.2. Описание типа возвращаемого значения

При разработке программного интерфейса библиотек **все** функции, возвращающие структуры
и таблицы значений (включая конструкторы), **обязательно** имеют описание типа возвращаемого
значения. Свойства структур и колонки таблиц значений описываются с новой строки, предваряясь
символом `*`.

```bsl
// Возвращаемое значение:
//   ТаблицаЗначений:
//     * Серия - СправочникСсылка.СерииНоменклатуры - если серия указана и она может
//               использоваться с новым значением номенклатуры на указанном складе,
//               то возвращается переданное значение; если нет - пустая ссылка.
//     * СтатусУказанияСерий - Число - если серии указываются в ТЧ "Товары", то
//               возвращается рассчитанный статус; если для переданной
//               номенклатуры/склада серии не используется - возвращается 0,
//               иначе возвращается переданный статус.
```

### 7.3. Вложенные описания

Перед именами вложенных свойств число звёздочек увеличивается: первый уровень вложенности —
2 звездочки, второй — 3 и т.д.

```bsl
// Параметры:
//  СведенияОбОбновлении - Структура:
//     * КодАдресногоОбъекта - Структура:
//        ** КодРегиона             - Число - код региона (длина - 2).
//        ** КодНаселенногоПункта   - Число - код населенного пункта (длина - 3).
//        ** КодУлицы               - Число - код улицы (длина - 4).
//     * Наименование        - Строка
//     * ОбновлениеДоступно  - Булево
```

### 7.4. Вызывающий код

В вызывающем коде **не следует** инициализировать структуру параметров, добавлять в неё
другие свойства, изменять состав и типы колонок таблицы значений. Во избежание неоднозначности
и скрытых ошибок все допустимые параметры вызываемой функции определяются явно
в функции-конструкторе параметров.

## 8. Параметр «Отказ» в обработчиках событий

> Стандарт: [Работа с параметром «Отказ» в обработчиках событий](https://its.1c.ru/db/v8std/content/686/hdoc) (std686)

### 8.1. Не присваивать Ложь

В обработчиках событий с параметром `Отказ` (`ПриЗаписи`, `ОбработкаПроверкиЗаполнения`,
`ТоварыПередНачаломДобавления` и т.п.) **не следует присваивать этому параметру значение
`Ложь`**.

Причина: параметр может устанавливаться в нескольких последовательных проверках (или
в нескольких подписках на одно событие), и к моменту очередной проверки он уже может
содержать `Истина` — можно ошибочно сбросить его обратно. При доработках на внедрении число
проверок может увеличиться.

```bsl
// Неправильно
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
    ...
    Отказ = ЕстьОшибкиЗаполнения();
    ...
КонецПроцедуры

// Правильно
Процедура ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)
    ...
    Если ЕстьОшибкиЗаполнения() Тогда
        Отказ = Истина;
    КонецЕсли;
    ...
КонецПроцедуры

// Правильно
Отказ = Отказ Или ЕстьОшибкиЗаполнения();
```

### 8.2. Другие аналогичные параметры

Требование распространяется на `СтандартнаяОбработка`, `Выполнение` и другие аналогичные
параметры обработчиков событий.

```bsl
Процедура ОбработкаПолученияДанныхВыбора(ДанныеВыбора, Параметры, СтандартнаяОбработка)

    Если Параметры.Свойства(...) Тогда
        СтандартнаяОбработка = Ложь;
        ...
    КонецЕсли;

КонецПроцедуры
```

### 8.3. Обязательно информировать пользователя

В событиях `ПриЗаписи`, `ПередЗаписью`, `ПередУдалением`, `ОбработкаПроведения`,
`ОбработкаПроверкиЗаполнения` и т.п. **неприемлемо** устанавливать `Отказ = Истина` без
информирования пользователя о причинах: сообщение вида «Не удалось записать "Заказ
покупателя"!» неинформативно и скрывает истинную причину, что требует значительных затрат
на расследование.

```bsl
// Неправильно
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

    Если Не ТоваровНаСкладеДостаточно() Тогда
        Отказ = Истина;
        Возврат;
    КонецЕсли;

КонецПроцедуры

// Правильно: пользователь уведомлён с помощью сообщения или исключения
Процедура ОбработкаПроведения(Отказ, РежимПроведения)

    Если Не ТоваровНаСкладеДостаточно() Тогда

        ТекстСообщения = СтрШаблон(НСтр("ru='Не хватает %1 %2 товара %3, на складе %4'"),
            Количество, ЕдиницаИзмерения, Товар, Склад);
        ОбщегоНазначения.СообщитьПользователю(ТекстСообщения, , "Объект.Товары", , Отказ);

    КонецЕсли;

КонецПроцедуры
```

## 9. Чек-лист код-ревью

### Текст модуля

- [ ] Текст на русском языке (кроме имён методов/параметров веб-сервисов и идентификаторов
      сторонних ИС).
- [ ] Нет буквы «ё» в тексте модуля (кроме интерфейсных текстов), нет неразрывных пробелов
      и «неправильных» минусов/тире.
- [ ] Нет неиспользуемых процедур и функций.
- [ ] Нет закомментированного кода, отладочного кода, `TODO`/`MRG`, фамилий разработчиков.
- [ ] Текст запроса не модифицируется комментариями и `СтрЗаменить`.
- [ ] Один оператор в одной строке (исключение — однотипные присваивания).
- [ ] Отступы — табуляция 4 символа, не пробелы.
- [ ] С левой позиции начинаются только `Процедура`/`Функция`/`КонецПроцедуры`/`КонецФункции`,
      заголовки процедур и функций, объявления переменных модуля, директивы компиляции,
      инструкции препроцессора, код вне процедур и функций.
- [ ] Строки не длиннее 120 символов (или перенос невозможен).
- [ ] Комментарии: в конце строки для коротких, отдельной строкой перед кодом для больших;
      пробел после `//`; деловой стиль.
- [ ] Тексты больших процедур разбиты на области с корректными именами.

### Структура модуля

- [ ] Разделы идут в установленном порядке (заголовок → переменные → программный интерфейс →
      обработчики событий → служебные → инициализация).
- [ ] Использованы области по шаблону для соответствующего вида модуля.
- [ ] Нет пустых областей.
- [ ] Есть заголовок модуля с описанием назначения (для форм — с параметрами формы).
- [ ] Все переменные модуля объявлены в `#Область ОписаниеПеременных` и снабжены
      комментарием.
- [ ] Экспортные процедуры и функции, не предназначенные для внешних потребителей,
      не помещены в «Программный интерфейс».
- [ ] У каждого события свой обработчик; общая логика вынесена в отдельную процедуру.
- [ ] Обработчики одного элемента формы расположены вместе; порядок соответствует панели
      свойств.
- [ ] В модуле формы нет группировки процедур «серверные / клиентские / без контекста».

### Имена

- [ ] Имена переменных, параметров и процедур/функций отражают термины предметной области.
- [ ] Слова слитно, каждое с прописной; предлоги и местоимения из одной буквы — прописные.
- [ ] Нет имён с подчёркиванием в начале и односимвольных имён (кроме счётчиков циклов).
- [ ] Флаги названы по истинному значению (`ЕстьОшибки`, `ЭтоТоварТара`).
- [ ] В именах не описаны типы параметров и возвращаемых значений.
- [ ] Процедуры — от неопределённой формы глагола (`ЗагрузитьКонтрагента`).
- [ ] Функции — от описания возвращаемого значения (`ПолноеИмяПользователя`),
      `Новый...` для создания объектов, `Это...`/причастие для проверок.

### Описание процедур и функций

- [ ] Все процедуры и функции программного интерфейса имеют комментарий-описание.
- [ ] Описание начинается с глагола, не дублирует имя процедуры/функции, не начинается
      с «Процедура…»/«Функция…».
- [ ] Секция «Параметры»: имя — тип (обязательно) — описание; тип — существующий
      платформенный или специальный тип EDT; `Массив из <тип>`; для `Структура`/
      `ТаблицаЗначений` — ссылка «см. …» на функцию-конструктор.
- [ ] Секция «Возвращаемое значение» есть у функций; составной тип — каждый тип с новой
      строки.
- [ ] Секция «Пример» вызывает функцию с именем общего модуля, показывает вход и выход.
      В переопределяемом модуле — пример реализации.
- [ ] Отступы в секциях комментария соблюдены; многострочное описание выровнено по второй
      строке.
- [ ] Помечена как «Устарела» и содержит ссылку на замену (если применимо).
- [ ] Комментарий расположен до директивы компиляции.
- [ ] Процедуры и функции отделены друг от друга пустыми строками.
- [ ] Нет избыточных комментариев, не дающих дополнительной информации.

### Параметры

- [ ] Параметры в логической последовательности «от общего к частному».
- [ ] Необязательные параметры — после обязательных.
- [ ] Не более ~7 параметров и не более ~3 со значениями по умолчанию; иначе —
      группировка в структуру или декомпозиция.
- [ ] Нет вложенных вызовов при передаче параметров (кроме компактных читаемых случаев).
- [ ] Нет вложенного `Новый Структура(...)` более чем с тремя свойствами.
- [ ] Нет пробелов перед `(`, после `(`, перед `)` и перед запятыми.
- [ ] Обязательные параметры не пропущены.

### Структуры и таблицы значений

- [ ] Для составных параметров есть функция-конструктор параметров.
- [ ] Параметры со значениями по умолчанию явно проинициализированы в конструкторе.
- [ ] Описание типа возвращаемого значения перечисляет свойства/колонки со `*`.
- [ ] Вложенные свойства описаны с увеличением числа звёздочек.
- [ ] Вызывающий код не добавляет свойства в структуру и не меняет состав колонок.

### Обработчики событий

- [ ] `Отказ` (и `СтандартнаяОбработка`, `Выполнение`) не сбрасывается в `Ложь`;
      используется `Отказ = Истина` или `Отказ = Отказ Или ...`.
- [ ] Установка `Отказ = Истина` сопровождается сообщением пользователю или исключением
      с указанием причины.
